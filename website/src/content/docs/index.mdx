  <h1>The graph that reacts.</h1>

  <p class="rg-tagline">
    Ripple is an immutable, reactive graph database for Cloudflare.
    One Durable Object writes. Segment trees live in R2. Datalog runs at the
    edge, next to your app. Built on Effect, typed end to end.
  </p>

<div class="rg-section">
  <h2>State the change.</h2>
  <p class="rg-lede">
    A change enters the system, travels through the field, and produces a
    coherent response. Write a row and every standing live query re-runs — no
    refetch, no invalidation call at the write site.
  </p>

  <div class="rg-split">
    <div>
      <h3>The catalog is the schema</h3>
      <p>
        Attributes, uniqueness, cardinality — plain TypeScript, checked at
        compile time. One catalog is shared by the deploy stack, the Worker,
        and the browser. No codegen.
      </p>
    </div>
    <div>

```ts
import * as Ripple from "@ripple/alchemy/db";
import * as Schema from "effect/Schema";

export const Todo = Ripple.Namespace("todo", {
  title: Ripple.Attr(Schema.String),
  done: Ripple.Attr(Schema.Boolean),
  createdAt: Ripple.Attr(Ripple.Instant),
});

export const Todos = Ripple.Catalog({ todo: Todo });
```

    </div>
  </div>
</div>

<div class="rg-section">
  <div class="rg-split">
    <div>
      <h3>Observe. Propagate. Resolve.</h3>
      <p>
        <code>transact</code> is a generator. <code>live</code> is a
        <code>Stream</code> on the session socket. A write advances the whole
        connection, so every standing query re-runs against the new basis.
      </p>
    </div>
    <div>

```ts
const todos = db.live((q) =>
  q.where("?e", Todo.title, "_").find("?e").pull({
    title: Todo.title,
    done: Todo.done,
  }),
);

await run(
  db.transact(function* (tx) {
    const t = yield* tx.entity();
    yield* t.add(Todo.title, "ship it");
    yield* t.add(Todo.done, false);
  }),
);
```

    <div>
      <h3>Deploy is one resource</h3>
      <p>
        A peer Worker, a <code>Ripple.Server</code>, a
        <code>Ripple.Database</code>. Alchemy provisions the Worker, the
        Durable Objects, and the R2 bucket; the catalog is installed before
        the UI connects.
      </p>
    </div>
    <div>

```ts
import * as Ripple from "@ripple/alchemy";
import * as Cloudflare from "alchemy/Cloudflare";

const Worker = Cloudflare.Worker("Peer", {
  main: "./packages/worker/src/index.ts",
});

export const Server = Ripple.Server("Ripple", { worker: Worker });
export const TodosDb = Ripple.Database("todos", {
  server: Server,
  catalog: Todos,
});
```

<div class="rg-section">
  <h2>Why Ripple.</h2>
  <p class="rg-lede">Reactive graph infrastructure for agentic systems — one exact sentence per claim.</p>

  <div class="rg-grid">
    <div class="rg-cell">
      <h3>Typed catalog</h3>
      <p>The schema is TypeScript. Attributes, uniqueness, and cardinality are checked at compile time, and <code>Pull</code> results type themselves from the pattern.</p>
    </div>
    <div class="rg-cell">
      <h3>Effect-native</h3>
      <p>Generator <code>transact</code>, literate <code>q</code>, <code>db.pull</code>. Every signature's requirements channel is <code>never</code> — one runtime runs everything.</p>
    </div>
    <div class="rg-cell">
      <h3>Live queries</h3>
      <p><code>db.live</code> is a <code>Stream</code> on the session socket. It survives dropped sockets and retries with backoff; teardown is fiber interruption.</p>
    </div>
    <div class="rg-cell">
      <h3>Db-per-tenant</h3>
      <p><code>ripple.db(name, catalog)</code> is pure — zero network per request. A database is a name; the first transaction materializes it.</p>
    </div>
    <div class="rg-cell">
      <h3>Time travel</h3>
      <p><code>db.asOf(t)</code> and <code>db.history</code> are views, not dumps. Queries compose over them unchanged, and you cannot transact into the past.</p>
    </div>
    <div class="rg-cell">
      <h3>Invariants as product</h3>
      <p>Single writer per database. Dense <code>t</code>. Persist-before-ack. Replicas are first-class — workers never read novelty from the transactor.</p>
    </div>
  </div>
</div>

<div class="rg-section">
  <h2>The shape of a deployment.</h2>
  <p class="rg-lede">
    One peer Worker, one Transactor Durable Object per logical database, N
    QueryReplica Durable Objects, one R2 bucket. Nothing else to run.
  </p>

  <div class="rg-invariants">
    <div>
      <h3>Single writer</h3>
      <p>Each database has exactly one Transactor. It serializes transactions and assigns <code>t</code> — total order, no coordination.</p>
    </div>
    <div>
      <h3>Dense t</h3>
      <p><code>t</code> is only ever read. No API mints, skips, or supplies one; the log is gap-free by construction.</p>
    </div>
    <div>
      <h3>Persist-before-ack</h3>
      <p><code>transact</code> resolves only with a <code>TxReport</code>, and its <code>dbAfter</code> is the read-your-writes fence.</p>
    </div>
    <div>
      <h3>Replicas first-class</h3>
      <p>Reads take their basis from the replica path. Immutable segments in R2 make every replica equally right.</p>
    </div>
  </div>
</div>
